# CLAUDE.md - guide for AI assistants (and humans) working on this repository

Open firmware for the Ajazz **AKP05E** stream dock (ArtInChip D13x, RISC-V, RT-Thread / Luban-Lite) plus a Windows host
tool. The firmware was reconstructed from a dump of the stock firmware and rebuilt on the unmodified ArtInChip SDK.
Read [README.md](README.md) for the overview and [docs/README.md](docs/README.md) for the documentation index.

## Where things are

| You want to change ... | Look in |
|---|---|
| the host protocol (commands, uploads, events) | `firmware/app/protocol.c` (parser), `firmware/app/threads.c` (`dispatch_command`, receive / image threads); document in `docs/host-protocol.md` |
| key matrix, encoders | `firmware/app/input.c` |
| touch strip | `firmware/app/touch.c` |
| LCD, logo, key images, boot screen version banner | `firmware/app/display.c` (+ `font5x7.h`, generated by `scripts/maintenance/gen_font5x7.py`) |
| backlight (PWM), watchdog | `firmware/app/backlight.c` |
| USB descriptors, HID endpoints, enumeration watchdog | `firmware/app/usb_hid.c`, `usb_desc_blob.inc` (stock bytes, do not edit) |
| buffers between USB and threads | `firmware/app/ringbuf.c`; allocation in `firmware/app/main.c` |
| pins, clocks | `firmware/board/akp05-nor/pinmux.c`, `sys_clk.c` |
| SDK options (what gets compiled) | `firmware/config/d13x_akp05-nor_rt-thread_akp05fw_defconfig` |
| partition layout, bootloader env | `firmware/image/image_cfg.json`, `env.txt` |
| image packing | `scripts/pack_image.py` |
| host tool | `host-tool/akp05_tool.py` (CLI, safety checks), `upg_proto.py` (protocol), `winhid.py` |
| test kit launchers | `host-tool/kit-template/*.bat` (English, numbered) |

All application functions are annotated `stock 0x........` (address in the original firmware); keep those notes when
you edit and add one when you add a reconstructed routine. The table is in `docs/stock-firmware.md`.

## Commands (Windows, PowerShell, project path without spaces)

```powershell
powershell -File scripts\setup.ps1                    # once: SDK clone + overlay + Ninja (needs network, ~4 GB)
powershell -File scripts\build.ps1 [-Clean] [-UsbDebug]   # build\images\d13x_os.itb etc.
powershell -File scripts\maintenance\refresh_sdk_sources.ps1   # REQUIRED after any change of firmware\config\*defconfig
powershell -File scripts\build_host_tool.ps1          # dist\akp05_tool.exe
powershell -File scripts\make_test_kit.ps1            # dist\akp05_test_kit (+ zip)
powershell -File scripts\clean.ps1 [-All]             # delete generated output (-All: also sdk\ and .local\)
$env:PYTHONPATH="host-tool"; python -m unittest discover -s host-tool/tests   # 24 tests, no hardware
```

CMake options: `-DAKP05_APP_LOG=0|1|2` (UART log level of the application), `-DAKP05_USB_DEBUG=ON`.
Identify a build on the UART by the line `[app] display build <date> <time>` (the "Firmware compile time" banner comes
from `main.c` only and does not change when other files change).

Releases are made by pushing a tag `v<AKP05_FW_VERSION>` (`.github/workflows/release.yml`, see `docs/releasing.md`). Never
attach a locally built kit to a release: it contains the private dump and the vendor updater.

## Hard rules

0. Keep the "use at your own risk, no responsibility for bricked devices" notices: README.md (top and Legal),
   docs/README.md, docs/boot-and-recovery.md, docs/host-tool.md, NOTICE, the kit README and the confirmation prompts of
   `akp05_tool.py`. Do not remove or weaken them.

1. **Never write the `spl` partition** and never add a code path that can. It is the only thing the recovery depends on.
2. **Never commit private data**: dumps (`*.bin`), the vendor updater (`*.img`, `*.aic`), the boot logo, anything under
   `private/`. `.gitignore` covers them; check `git status` before committing. No manufacturer binary belongs here.
3. Do not run a flash or touch a real device without the user's explicit go-ahead. Dry run first, `--write` last. Make
   sure a dump exists and the recovery path (PA.0 strap, `docs/boot-and-recovery.md`) is available.
4. Keep the allocation split in `app_resources_init()` (img_buf: `rt_malloc`, stage buffer: `aicos_malloc(MEM_CMA)`). Other
   splits broke uploads or the USB enumeration (`docs/troubleshooting.md`).
5. The FIT must keep the `version` property and the `hash-*` nodes (`pack_image.py`), the load / entry address
   `0x40210000`, and `CONFIG_AIC_PSRAM_SW_SIZE=0x210000`.
6. The defconfig is applied with `scons --apply-def`, which does not evaluate Kconfig defaults: list derived options
   explicitly, then run `refresh_sdk_sources.ps1` (it regenerates `cmake/sdk_sources.cmake`, which is committed).
7. USB: keep the CherryUSB **CPU** mode (`..._AIC_CPU`); the DMA mode breaks EP0 data stages.
8. Generated paths (`sdk/`, `build/`, `dist/`, `.local/`) are never edited by hand and never committed.

## Conventions

* Everything in the repository is **English**: code comments, messages, scripts, documentation, launcher names.
* No `goto` anywhere (C, batch files, scripts): use early returns, nested blocks or small helper functions. The kit
  launchers are plain top-to-bottom batch files (no labels), and the repository has none to maintain.
* C: 4 spaces, kernel-style braces, `stock 0x...` notes for reconstructed routines, UART diagnostics through
  `app_log()` / `app_err()` (levels in `firmware/app/akp05_app.h`), not bare `printf`.
* Python (host tool): standard library only for the default path (ctypes for the Windows HID API); tests use software
  models of the device in `host-tool/tests`. Add a test for every protocol rule you learn.
* Scripts: PowerShell 5.1 compatible. Every script that changes the directory or the environment wraps its body in
  `Save-Session` / `try` / `finally { Restore-Session }` (`scripts/lib/session.ps1`) and runs the preflight checks of
  `scripts/lib/checks.ps1`. Wrap noisy native tools in `cmd /c` (stderr would become errors), call the SDK's
  Python by full path (after `Enter-Sdk` the `python` on PATH is 2.7).
* Do not write scripts or sources with shell here-documents that contain backslash escapes; use a file-writing tool and
  verify the result. `.gitignore` has no trailing comments.
* Anything that changes what a host sees (event codes, states, timing, ordering) is documented in `docs/host-protocol.md`
  section 5 ("Differences from the stock firmware"): plugins depend on it.
* Documentation changes go together with the code change: protocol -> `docs/host-protocol.md` or
  `docs/bootloader-protocol.md`; new pitfall -> `docs/troubleshooting.md`; verified / unverified -> `docs/testing.md`.

## How to verify a change

* Host tool: the unit tests. Firmware: build, flash (with the user's approval), watch the UART. The expected boot log is in
  `docs/boot-and-recovery.md` section 1 and the checklist in `docs/testing.md`.
* `scripts/analysis/compare_with_stock.py` compares rebuilt functions with the stock code (needs `private/stock-dump`).
* Hardware-verified (see `docs/testing.md`): everything except the GitHub Actions `firmware` job.
  The occasional "HID does not come up after plug-in" was the duplicate SETUP report of the CherryUSB port, and resets under
  fast knob / key use were the unserialised IN frames; both are fixed in `usb_hid.c` and verified (`docs/troubleshooting.md`).
  Still open: the freeze with the original vendor application is only partly explained (see the status line / `usb trace`).

## Useful facts

* Device ids: running firmware `0300:3004` (HID, vendor page FFA0 + keyboard); HID bootloader `33C3:8899`;
  BootROM / updater `33C3:6677`. UART: 115200 8N1 on the PA.0 (TX) / PA.1 (RX) pads, 3.3 V.
* Reboot into the bootloader: host command `CRT APPNEW` or `upghid` on the UART (reboot reason 6).
  Forced BootROM mode: PA.0 to GND at power-on.
* Stock analysis exports live in `private/analysis/` (Ghidra cannot decode the T-Head `xtheade` instructions; use the SDK
  `riscv64-unknown-elf-objdump` for exact disassembly).
